## Architectural decisions made during the lift that were not in the original instructions

1. **`packages/webview/src/graph/layout/layout-protocol.ts` is a new file** (no claudemap analog). The worker message protocol is its own module so the worker bundle does not transitively import React or DOM-only modules from the wrapper file.
2. **`packages/skill/src/mcp/tool-definition.ts` is a new file** (no claudemap analog). Splitting the `ToolDefinition` interface out of `server.ts` lets each tool-family file import only the type without pulling in the MCP SDK at import time. Same pattern as the layout-protocol decision: keep contracts separate from impls.
3. **`packages/webview/src/graph/nodes/shared/nodeChrome.tsx` is a new file** (no claudemap analog as a single component, though SystemNode/FileNode/FunctionNode supply the visual vocabulary). The lift instructions called for "extract the styling vocabulary into nodes/shared/nodeChrome.tsx so all eight node types compose it" — this is the file. (IntentGraph has nine node kinds, not eight; the `counterexample` kind from Tech-Spec §4.1 was missing from the prompt's enumeration but is part of the schema.)
4. **`fileWalker.ts` output dropped `lineCount`** — replaced with `byteSize`. The lift instructions said "no lineCount as a primitive on the file (tree-sitter computes a richer metric)." `byteSize` is kept because it is not a code metric (it is a deterministic file property) and is useful for the SQLite seed step.
5. **`fileWalker.ts` keeps `pnpm-lock.yaml` in `SKIPPED_FILE_NAMES`** alongside claudemap's `package-lock.json` and `yarn.lock`. IntentGraph is a pnpm monorepo; the lockfile is large and not source.
6. **`useZoomLevel` defaults to `overviewBelow=0.6, midBelow=1.5`**, slightly wider than ClaudeMap's `overview=0.5, detailed=1.5`. IntentGraph's intent graph is denser at the top (concept boundaries hold many intent children) so the overview tier benefits from being wider. Configurable via the hook argument.
7. **`scripts/check-contracts.ts` is a structural check, not a column-by-column check**, while `packages/skill/src/db/schema.ts` is still a Phase 0 stub. The script gracefully passes that check with a "deferred until Phase 2" notice when it sees the placeholder. Once `sqliteTable(...)` bindings land the check tightens automatically.
8. **`packages/skill/tsconfig.json` dropped `composite: true` and the project reference to `../shared`.** Reason: under `moduleResolution: Bundler` with `@intentgraph/shared`'s `main: ./src/index.ts` field, TypeScript reads the source directly. The composite reference required `tsc -b` to build shared first, which collided with `noEmit` (TS6310). Dropping the reference keeps `pnpm typecheck` working with a single `tsc --noEmit` invocation. If we later need declaration emit for shared (e.g. publishing), reintroduce the reference and switch the typecheck script to `tsc -b --noEmit` once TS supports that combination cleanly.
9. **`packages/agent-skill/tsconfig.json` switched to `allowJs: true` with `.js`/`.mjs` includes.** The original include patterns matched `.ts`/`.tsx` only and produced `TS18003: No inputs were found` because the package's only files are `bin/intentgraph-skill.js` and `scripts/copy-skill.mjs`. The package has no real TypeScript source.
10. **Root `pnpm test` script gained `--passWithNoTests`.** The repo currently has no test files (`tests/` directories are `.gitkeep` only). Without the flag, vitest exits 1 even though there is nothing wrong. The flag preserves the gate when real tests land.
11. **ESLint ignores `claudemap/**` and `artifacts/**`.** The `claudemap/` tree is the read-only reference fork; the lifter skill is the only path that reads it, and we should not bind ourselves to upstream style. `artifacts/**` is the agent-skill packager output.
12. **`packages/webview/package.json` gained `lucide-react@^0.468.0`.** The lifted node icons depend on it. ClaudeMap had it as a transitive dep through its app package; IntentGraph's webview package needed it explicitly.
13. **The `agent-skill` packager bundles the built skill under `skill-dist/`**, so the published artifact is self-contained. The published `bin/intentgraph-skill.js` then re-resolves through `@intentgraph/skill` which in the published artifact points at the bundled directory. The ClaudeMap layout assumed the `npm install` step at install time would bring the runtime in; IntentGraph avoids that because the skill's better-sqlite3 native dep is fragile to install in arbitrary user repos.
14. **The `agent-skill` install / package / smoke-test scripts now live under repo-root `scripts/`** rather than under `packages/agent-skill/scripts/`. Reason: they orchestrate across packages (they need the built `@intentgraph/skill` artifact and the agent-skill source); putting them at the repo root makes the dependency direction obvious. The existing `packages/agent-skill/scripts/copy-skill.mjs` (a build-readiness check) stays where it is.
